# Java Servlet + Angular + PostgreSQL 学習プロジェクト 作業メモ

## 目的

Windows PCだけでWebアプリ開発環境を構築し、最終的に仮想マシン上のサーバーへデプロイするまでを学習する。

題材として、厚生労働省のメンタルヘルステストを参考にした簡単なサンプルアプリを作成する。

最終的な構成イメージ：

```text
Angular
   ↓ HTTP / JSON
Java Servlet
   ↓
PostgreSQL
```

開発環境：
Windows 11 Pro + VSCode

最終的には仮想マシン上のサーバーへデプロイする。

Angularの画面は、動作確認後にポップなデザインへ変更していく。

---

## 現在の環境

- OS: Windows 11 Pro
- IDE: VSCode
- Java: 17

- PostgreSQL: 環境構築済み
- Angular: 使用予定

## 1. Javaプロジェクト

Mavenプロジェクトを作成。

```text
groupId: com.example
artifactId: mental-api
version: 1.0-SNAPSHOT
packaging: war
```

`pom.xml` には、

```xml
<packaging>war</packaging>
```

が設定されている。

そのため、TomcatへデプロイするWARを作成する構成になっている。

---

## 2. Servlet API

Tomcat 10.1.60を使用しているため、Jakarta Servlet APIを使用する。

```xml
<dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <version>6.0.0</version>
    <scope>provided</scope>
</dependency>
```

Javaコードでは、

```java
import jakarta.servlet.*;
```

を使用する。

`javax.servlet.*` ではない。

---

## 3. Mavenについて分かったこと

PowerShellで、

```powershell
mvn
```

を実行したところ、Mavenコマンドが認識されなかった。

確認したところ、存在していたMaven関連ファイルは、

```text
C:\Users\xxx\.vscode\extensions\vscjava.vscode-maven-0.45.3\resources\maven-wrapper
```

だった。

これはVSCodeのMaven拡張に関連するMaven Wrapperであり、WindowsにMaven本体をインストールしてPATHを設定した状態とは異なる。

今後、Mavenをコマンドラインから使うためには、Maven本体をWindowsへ導入してPATHを設定する必要がある。

---

## 4. QuestionServlet

作成したServletでは、

```java
@WebServlet("/api/questions")
```

としている。

簡易的な3つの質問をJacksonでJSONに変換して返す。

APIのアクセス先：

```text
http://localhost:8080/mental-api/api/questions
```

---

## 5. 最初の404エラー

最初、

```text
http://localhost:8080/mental-api/api/questions
```

へアクセスすると404になった。

Tomcat自体は、

```text
Apache Tomcat/10.1.60
```

として起動していた。

ログには、

```text
CATALINA_BASE: C:\tomcat10\apache-tomcat-10.1.60
CATALINA_HOME: C:\tomcat10\apache-tomcat-10.1.60
```

が表示されていた。

一方、

```text
Deploying web application archive
```

というデプロイログが見つからなかった。

---

## 6. VSCodeのServersについて

VSCodeのSERVERSには、

```text
SERVERS
└─ Tomcat 10.x
   └─ mental-api.war
```

と表示されていた。

しかし、実際のTomcatの、

```text
C:\tomcat10\apache-tomcat-10.1.60\webapps
```

には、

```text
mental-api.war
```

が存在していなかった。

VSCodeのServersにWARが表示されていることと、実際のTomcatの`webapps`にWARが配置されていることは、今回の環境では同じではなかった。

---

## 7. WARをTomcatへ配置して解決

Tomcatを停止した状態で、

```text
mental-api.war
```

を、

```text
C:\tomcat10\apache-tomcat-10.1.60\webapps\
```

へコピーした。

その後、VSCodeのSERVERSからTomcatを起動した。

TomcatがWARを展開し、Servletが利用可能になった。

---

## 8. API動作確認

ブラウザで、

```text
http://localhost:8080/mental-api/api/questions
```

へアクセス。

以下のJSONが表示された。

```json
[
  "最近、よく眠れていますか？",
  "仕事や勉強に集中できていますか？",
  "理由もなく不安になることがありますか？"
]
```

これにより、以下の流れが正常に動作することを確認できた。

```text
Java Servlet
    ↓
MavenでWAR作成
    ↓
mental-api.war
    ↓
Tomcat 10.1.60
    ↓
HTTPリクエスト
    ↓
QuestionServlet
    ↓
JSONレスポンス
    ↓
ブラウザ
```
